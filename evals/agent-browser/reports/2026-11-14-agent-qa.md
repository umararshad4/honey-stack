# agent-browser vs Playwright MCP for agent-driven QA — 2026-11-14

An agent ran the same exploratory flow through each tool: open the task desk fixture (`../webmcp/benchmark/server.mjs`), snapshot, open the dialog, snapshot, fill the title, pick High, save, snapshot and check the new row, complete it, search, snapshot and check the filter, then take a screenshot. Refs come from each tool's own latest snapshot, the way an agent would read them. The flow fails if the task isn't created or the search doesn't filter.

| Mode | Runs | Median wall time | Range | Tool calls | Text the agent reads | ≈ Tokens |
|---|---:|---:|---:|---:|---:|---:|
| **agent-browser `snapshot -i`** | 10 | 3.13s | 2.53–4.03s | 12 | **1,078 chars** | **≈270** |
| agent-browser full `snapshot` | 10 | 2.89s | 1.85–4.01s | 12 | 2,240 chars | ≈560 |
| Playwright MCP 0.0.85 | 10 | 3.13s | 2.88–3.39s | 13 | 4,922 chars | ≈1,231 |

- **Wall time is a tie.** The median is 3.13s for both, and agent-browser's spread is wider. On this fixture, browser start-up and action latency are not where any gain comes from.
- **Context per run is 4.6× smaller** (78% less text) with `snapshot -i`, and 2.2× smaller even with full snapshots. Each agent step reads less, so model turns get cheaper and faster, and a long session runs longer before it fills its context. This benchmark doesn't measure model time: it scripts the agent's decisions.
- Playwright MCP 0.0.85 links each action's snapshot as a file instead of returning it, so the agent spends one extra `browser_snapshot` call to read refs inline.

## Protocol

- One excluded warm-up round, then 10 measured rounds with the mode order rotated each round, one command at a time. Each run starts a fresh browser (`--session` per run for agent-browser, `--isolated --headless` for Playwright MCP) and closes it, all inside the timer.
- Characters are the tool output text returned to the agent, with screenshot bytes excluded. Tokens are estimated as chars/4.
- Machine: Apple M1, 8 GB, Darwin 27.0.0, Node 24.18.0, with normal desktop apps running. agent-browser 0.43.0 and @playwright/mcp 0.0.85 both drive the installed Google Chrome 157.0.8103.51.
- Scope: one small page and one flow. A larger DOM probably widens the gap in text size, but that hasn't been measured. This doesn't replace prepared e2e suites; those run with no model in the loop (see `../webmcp/reports/`).

Raw per-run data: [2026-11-14-agent-qa.json](2026-11-14-agent-qa.json). Reproduce with `npm ci && npm run benchmark` in `evals/agent-browser` (`ROUNDS=10` to match).
